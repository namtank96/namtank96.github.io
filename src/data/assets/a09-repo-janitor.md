## 이 규칙의 근거

**자동 삭제 금지.** 정리 도구가 필요한 파일을 한 번이라도 삭제하면 이후 사용되지 않습니다.
무엇이 필요한지는 리포를 구성한 사람만 판단할 수 있습니다. 에이전트의 역할은 **탐색과 분류**이며,
삭제 판단은 사람의 몫입니다. glob 일괄 삭제도 같은 이유로 금지합니다.
패턴 삭제는 의도하지 않은 파일까지 포함시킵니다.

**삭제와 추적해제 분리.** 삭제 대상으로 분류되는 항목의 다수는 **저장소에서만 제외하면 되는 파일**입니다.
실행 결과나 빌드 산출물은 로컬에서는 유용하고 커밋된 상태에서는 방해가 됩니다.
두 항목을 하나로 묶어 제안하면 필요한 파일까지 삭제하게 됩니다.

**다른 자동화의 입력인지 확인.** 실제 사고 사례에서 도출한 규칙입니다.
저장소에 있던 실행 결과 JSON을 정리한 뒤, PC가 꺼진 상태로 실행되는 감사 작업이
입력을 찾지 못해 실패했습니다. 로컬에서는 정상 동작했기 때문에 발견이 늦었습니다.
이런 항목은 후보로 올리지 않고 "확인 필요"로만 표시합니다.

**보관 폴더 제외.** 이전 버전을 남기는 것은 규칙에 따른 조치입니다.
정리 도구가 보관 폴더를 후보로 올리면 이 규칙이 유지되지 않습니다.
용량만 보고하고 판단은 사람에게 넘깁니다.

**절감량 실측.** 추정치는 검증되지 않으며, 검증되지 않은 수치는 시간이 지나면 부정확해집니다.
전후 실측은 명령 두 줄로 가능합니다.
