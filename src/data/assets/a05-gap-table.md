## 출력 예시

0단계에서 후보 목록의 빈 곳을 먼저 잡습니다.

```
0. 누락 축 점검

  제시하신 후보 5종은 빌더·카탈로그 영역은 덮지만, 두 축이 비어 있습니다.

  - 실행 추적 — 이 영역에는 사실상 표준으로 취급되는 것이 따로 있습니다.
    지금 목록으로는 이 조각을 대조할 대상이 없습니다.
  - 사이드 패널 UX — 이 패턴의 원본이 되는 것이 목록에 없습니다.

  두 개를 추가하고 진행할까요?
```

본표는 3열이 다 차야만 남습니다.

```
### P0 — 진입 경험 (가장 어색한 지점)

현재: 입력을 모달에서 받고, 확정하면 별도 화면으로 점프합니다.
이중 표면 + 컨텍스트 단절이 어색함의 정체입니다.

| 항목 | 현재 우리 | 베낄 요소 | 얹을 신규 |
|---|---|---|---|
| 입력 표면 | 모달 안에서 전부 처리 | 입력이 작업 캔버스에 바로 전개, 모달 없음 | 모달은 한 줄 입력까지만, 전개는 본 화면에서 |
| 화면 간 연속성 | 모달의 결과가 소멸하고 본 화면은 새로 그림 | 생성 직후 같은 구조가 편집기로 그대로 이어짐 | 같은 노드·같은 위치로 인계 후 페이드 전환 |
| 착지 첫인상 | 진입 시 빈 화면 | 작업 영역과 보조 패널이 처음부터 채워짐 | 착지 즉시 "N단계 중 1단계" 요약 + 첫 액션 포커스 |

권고: 모달을 없애지 말고 얇게 만듭니다.

**P0의 3행이 곧 변경 명세다.**
```

## 이 규칙의 근거

**왜 통째 비교를 금지하는가.** "우리 플랫폼 vs 저쪽 플랫폼"으로 시작하면 범위가 커서 반드시 막힙니다.
막히면 결론이 "전반적으로 부족하다"가 되고, 그건 아무 작업 지시도 만들지 못합니다.
조각으로 쪼개는 순간 각 조각은 한 시간이면 대조가 끝납니다.

**왜 조각당 대상을 하나로 제한하는가.** 여러 개를 붙이면 "A는 이게 좋고 B는 저게 좋고"가 되면서
결론이 흐려집니다. 하나만 고르게 하면 **"왜 그것인가"를 답해야 하고**, 그 답 자체가 분석입니다.

**왜 3열이 안 차면 행을 버리는가.** 셋 중 하나가 비었다는 건 그 행이 벤치마킹이 아니라는 뜻입니다.
"현재 우리"가 없으면 신규 기획이고, "베낄 요소"가 없으면 대상을 잘못 골랐고,
"얹을 신규"가 없으면 그냥 따라하는 겁니다. 억지로 채운 행이 표를 길게 만들고 신뢰를 깎습니다.

**왜 P0 기준이 기능 격차가 아니라 어색함인가.** 기능 개수 차이는 대개 나중에 메워도 되는 것이고,
쓰는 사람이 걸려 넘어지는 지점은 지금 메워야 하는 것입니다. 그리고 어색한 지점은
경쟁 제품이 이미 풀어놨을 가능성이 높아서 베낄 요소가 확실히 나옵니다.

**왜 마지막 줄을 고정하는가.** 벤치마킹 문서는 분석으로 끝나기 쉽습니다.
"P0의 N행이 곧 변경 명세다"라는 문장 하나가 문서를 작업 지시로 착지시킵니다.
이 줄이 없으면 잘 만든 표가 폴더에만 남습니다.

**왜 누락 축을 먼저 묻는가.** 후보 목록은 내가 아는 것으로만 채워집니다.
내가 모르는 영역의 사실상 표준은 목록에 없고, 없으니 아무도 묻지 않고, 영영 안 보입니다.
"내 목록에 없는데 있어야 할 것은?"이라는 질문 하나가 이걸 잡습니다.
