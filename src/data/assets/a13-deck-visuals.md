## 출력 예시

라이브러리 정책이 실제로 작동하는 모습입니다.

```
요청: 8단계 프로세스 루프 도식. 단계를 클릭하면 근거가 펼쳐지게.

확인: 이 파일이 어디서 열리나요?
  (a) 제품 화면 안         → 인라인 SVG + CSS 만. 외부 라이브러리 0
  (b) 독립 파일로 공유     → 오픈소스 가능, 단 로컬 보관 필수

→ (b) 로 진행합니다.

만든 것: 단일 HTML 1개 (도식 + 인터랙션 + 스타일 전부 임베드)
  · 라이브러리: 모션 라이브러리 1종을 파일 안에 임베드했습니다. CDN 참조 없음
  · 색: 주색·분류색 5종·상태색 3종 전부 전달받은 토큰 그대로. 신규 색 0
  · 아이콘: 지정 라이브러리 1종, stroke 1.5px, currentColor

⚠ 확인 부탁드립니다: 네트워크를 끊고 파일을 더블클릭해 열어보세요.
  도식이 그대로 뜨면 정상입니다. 이 확인은 제가 대신 못 합니다.
```

## 이 규칙의 근거

**오프라인에서 열리는지를 강제하는 것.** 이 파일은 메일로 나가고, 회의실에서 열리고,
사내망 밖에서 열립니다. CDN 하나만 참조해도 발표 5분 전에 도식이 빈칸으로 뜹니다.
실제로 나는 사고입니다. 그 순간 복구할 방법이 없습니다.
라이브러리를 파일 안에 넣는 비용은 몇 KB이고, 안 넣어서 치르는 비용은 발표 하나입니다.

**만드는 쪽과 규율을 정하는 쪽을 나누는 것.** 한 에이전트가 색도 정하고 도식도 만들면,
도식을 예쁘게 만들려고 색을 바꿉니다. 자료마다 색이 조금씩 달라지고,
전체를 모아놨을 때 따로 놉니다. 토큰을 소비만 하게 하면 이 드리프트가 구조적으로 막힙니다.

**산출물 위치에 따라 규칙을 나누는 것.** 제품 안에 들어가는 것과 독립 파일은 제약이 다릅니다.
제품은 번들·성능·의존성 관리가 걸려 있고, 독립 파일은 "어디서든 열려야 한다"가 걸려 있습니다.
한 규칙으로 묶으면 둘 중 하나는 과하게 제한됩니다.

**라이브러리 기본 팔레트를 못 쓰게 하는 것.** 기본 팔레트를 그대로 둔 도식은
가져다 붙인 것으로 읽힙니다. 내용이 아무리 좋아도 그렇게 보입니다.
토큰으로 덮는 데는 몇 줄이면 됩니다. 안 덮으면 자료 전체의 신뢰도가 내려갑니다.

**이모지 금지.** 이모지는 OS마다 다르게 렌더됩니다.
내 화면에서 괜찮던 것이 상대 화면에서는 다른 그림입니다. 아이콘 라이브러리와
획 굵기가 달라서 섞이는 순간 티도 납니다.
