## 출력 예시

§4 게이트가 이 문서의 존재 이유입니다.

```markdown
## 4. 작성 순서 — 게이트

1. 원칙 (L0)              ✅ 확정
2. 입력 규격 (L1)         ✅ 확정 v1.0
3. 도출 규격 (L1)         ✅ 확정 v1.0
4. 출력 규격 (L1)         🔨 작성 중        ← 현재
5. ★ 첫 건을 손으로 완주   ⛔ 게이트
6. 하네스 (L3)            ⏸ 5번 통과 전 착수 금지
7. 검증 (L3)              ⏸
8. 축적 (L3)              ⏸
```

6~8번에 "착수 금지"가 적혀 있는 것이 핵심입니다.
자동화는 언제나 지금 만들고 싶고, 만들면 진척이 실감 납니다.
그런데 5번을 안 거치면 **판단해야 할 곳을 자동화하고 반복을 남겨둡니다.**

일람은 상태를 반드시 답니다.

```markdown
| 문서 | 역할 | 상태 |
|---|---|---|
| docs/PRINCIPLES.md | 규격이 왜 그 모양인지의 근거 | 확정 v1.0 |
| docs/INPUT-SPEC.md | 입력 형식. 스키마와 동기 | 확정 v1.0 |
| docs/OUTPUT-SPEC.md | 출력 형식 | 작성 중 |
| docs/HARNESS.md | 실행 하네스 | 초안 — 사용 금지 |
```

`초안 — 사용 금지`를 일람에서 빼지 않는 것이 중요합니다.
빼면 누군가 같은 문서를 다시 만듭니다.

## 이 규칙의 근거

**왜 문서를 종류가 아니라 바뀌는 속도로 나누는가.** "기획/개발/운영"으로 나누면
한 폴더 안에 매일 바뀌는 것과 반년에 한 번 바뀌는 것이 섞입니다.
속도로 나누면 **아래층이 바뀔 때 위층은 안 봐도 된다**는 판단이 가능해집니다.
그게 문서가 많아졌을 때 실제로 필요한 정보입니다.

**왜 위층이 아래층을 이기게 하는가.** 규칙과 규격이 어긋났을 때 어느 쪽이 진짜인지
매번 논쟁하면 그 논쟁이 반복됩니다. 우선순위를 한 번 정해두면 논쟁이 없어집니다.

**왜 화살표를 거스르는 참조를 금지하는가.** 규격이 하네스를 참조하기 시작하면 순환이 생깁니다.
순환이 생기면 "무엇을 먼저 고쳐야 하나"에 답이 없어지고, 그때부터 문서 세트가 통째로 굳습니다.

**왜 게이트를 두는가.** 순서를 안 정하면 항상 재미있는 것부터 합니다.
자동화가 가장 재미있고, 규격이 가장 지루합니다. 그런데 규격 없이 만든 자동화는
규격이 정해지는 순간 다시 만들어야 합니다. **게이트 한 줄이 그 재작업을 막습니다.**

**왜 현재 위치를 이 문서에만 표시하는가.** 진행 상태를 여러 문서에 흩어두면
어디가 진짜인지 모르게 되고, 서로 다른 상태를 가리키기 시작합니다.
`← 현재` 한 줄을 한 곳에만 두면 그 문제가 없습니다.

**왜 폐기 문서를 남기는가.** 지운 이유가 다음 사람의 자산입니다.
그리고 지운 기록이 없으면 반년 뒤에 같은 문서를 다시 만듭니다.
