  - 변환 가능한 HTML 구조 사전 규격화 및 규격 밖 구조의 이미지 폴백 처리
  - 슬라이드 템플릿 · 디자인 시스템의 코드 분리 (서식 변경 시 변환기 수정 불필요)
judgment:
  - call: 이미지 대신 네이티브 객체로 변환
    why: >-
      덱은 최소 한 번은 수신자 측에서 수정됩니다. 이미지로 전달하면 수정이 불가능해 실무
      사용으로 이어지지 않습니다. 네이티브 객체 변환을 전제로 파이프라인을 설계했습니다.
  - call: 변환 가능 범위를 규격으로 선정의
    why: >-
      규격 없이 착수하면 매번 다른 입력에 개별 대응하는 작업으로 수렴합니다. 변환 가능한
      구조를 먼저 확정하면 그 밖의 입력은 폴백으로 처리됩니다. 입력을 작성하는 쪽도 규격을
      기준으로 삼습니다.
